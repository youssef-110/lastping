Heartbeats for anything on a schedule

Give each job a ping URL. Use a simple interval or a real cron expression, plus a grace window. If the ping is late, the check goes late, then down, and you hear about it once, not fifty times.

  • Cron expressions with a live preview of the next runs
  • Report exit codes: /ping/<id>/$?
  • Measure run time with /start, attach logs on /fail
crontabreceiving
# back up nightly, then report the exit code
0 3 * * *  ./backup.sh; \
  curl -fsS -m 10 lastping.app/ping/8f2c…/$?

# → 03:00:41  ping  ran 38.2 s
# → next run  tomorrow 03:00 UTC

Uptime checks without the noise

Probe any website or API from Cloudflare's network every minute. A check only goes down after two failures in a row, so a single blip never wakes you up.

  • Recovery alerts when it comes back

How it works

Three steps. About sixty seconds.

01

02

FAQ

          
Questions, answered.

        

        

          
What's the difference between a heartbeat and an uptime check?
A heartbeat waits for your job to call Lastping. Use it for cron jobs, backups and workers. An uptime check makes Lastping call your site every minute. Use it for websites and APIs.

          
Do I need an account?
No. You can create a project instantly and manage it with a private dashboard link. Sign in with a passkey when you want your projects on every device.

          
What is a passkey?
A passkey replaces a password with your device's fingerprint, face or PIN. Nothing to remember, nothing to leak, and it syncs through iCloud Keychain, Google Password Manager or Windows.

          
How fast will I be alerted?
Lastping sweeps every minute. A heartbeat alerts as soon as its grace time runs out; a failed exit code alerts immediately. Uptime checks alert after two failed probes in a row.

          
Is it open source?
Yes, MIT licensed. It runs on Cloudflare Workers and D1, and you can self-host it on the free tier in a few minutes.
